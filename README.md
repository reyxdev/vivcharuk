# Вівчарик — код сайту

Будується за блупринтом у [docs/](docs/00-README.md). Порядок авторитету — у [CLAUDE.md](CLAUDE.md).

## Склад

| Шлях | Що це |
|---|---|
| `apps/api` | Fastify 5 + Prisma 6 + pg-boss. REST `/api/v1`, вхід персоналу з 2FA |
| `apps/storefront` | React Router 7 (framework mode) + Vite + Tailwind 4. Вітрина, SSR |
| `apps/admin` | Vite SPA. Панель керування під `/admin` |
| `packages/schemas` | Спільні Zod-схеми, коди помилок, дозволи, дані бізнесу (заглушки) |
| `packages/tokens` | Токени дизайну → `tokens.css` + `theme.css` для Tailwind 4 |
| `prisma/` | Схема, міграції, початкові дані |

## Запуск локально

Однією командою (Kali, Debian, Ubuntu; потрібні Node.js 22+ і Docker):

```bash
./start.sh
```

Перший запуск створює `.env` з новими випадковими секретами, базу Postgres у Docker, ставить
пакети, проганяє міграції й заповнює базу (з демо-товарами) і друкує одноразовий пароль власника
для панелі. Далі: вітрина http://127.0.0.1:5173/uk/, панель http://127.0.0.1:3000/admin/,
Ctrl+C зупиняє все, дані в базі лишаються.

Те саме вручну:

```bash
npm install
npm run db:up                                  # Postgres 16 у Docker, порт 5434
npx prisma migrate deploy
npx tsx --env-file=.env prisma/seed/index.ts   # дозволи, ролі, власник
npm run build:tokens
npm run dev:api                                # http://127.0.0.1:3000/api/v1/health
npm run dev -w @vivcharyk/storefront           # http://localhost:5173/uk/
npm run dev:admin                              # http://localhost:5174/admin/
```

## Викласти на сервер

Домен має вказувати на IP сервера (A-запис). Потім з цього комп'ютера однією командою:

```bash
./deploy/push.sh root@IP-сервера vivcharuk.com
```

Скрипт завантажує код на сервер і запускає там `deploy/install.sh`: Docker, Node.js 22, база Postgres
(лише локально), HTTPS через Caddy, дві служби systemd, файрвол і щоденна копія бази (14 днів, у
`/var/backups/vivcharyk`). Перший запуск друкує одноразовий пароль власника для панелі. Повторний
запуск тієї ж команди — це оновлення сайту: `.env`, база й сертифікати на сервері не чіпаються.

## Заглушки

Факти, яких ще немає (ФОП, ЄДРПОУ, адреса, телефони, ключі WayForPay тощо), стоять як
`[… — заглушка]` у `packages/schemas/src/business.ts` і як порожні змінні середовища.
Їх заповнюють наприкінці, коли клієнт дасть дані. Нічого не вигадується.

Змінні середовища, які заповнюються пізніше (порожні = вимкнено):

| Змінна | Що вмикає |
|---|---|
| `STAFF_TOKEN_SECRET` | Обов'язкова: підпис посилань-запрошень і скидання пароля (окремо від сесій) |
| `TELEGRAM_BOT_TOKEN` | Сповіщення в Telegram; ID чату задається в панелі, «Налаштування» |
| `SITE_URL` | Публічна адреса сайту (`https://vivcharuk.com`) для canonical, hreflang, карти сайту й robots.txt; її читають і API, і сайт |
| `VITE_GA_ID` | Google Analytics 4 (`G-…`), лише після «Прийняти всі» в банері cookie; порожньо — банер на сайті не показується |
| `HIBP_ENABLED` | Перевірка паролів співробітників за базою зламаних паролів Have I Been Pwned (назовні йдуть лише перші 5 символів SHA-1). Типово увімкнено; `false` — вимкнути |
| `ADMIN_URL` | Адреса панелі в посиланнях зі сповіщень |
| `CLOUDINARY_URL` | Завантаження фото; до того правило «щонайменше 3 фото» не блокує публікацію |
| `NOVA_POSHTA_API_KEY` | Справжні міста й відділення Нової пошти |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | Листи покупцям (замовлення прийнято, оплату отримано, відправлено) і працівникам (запрошення, новий пароль) через поштову скриньку магазину на Porkbun: `smtp.porkbun.com`, порт 587. Порожньо — листи не надсилаються; під час розробки вони лягають у `mail-outbox/` для перегляду |
| `PAYMENTS_STUB`, `SHIPPING_TEST_RATES` | Лише для розробки: тестова оплата й тариф 1 ₴ |

Фонові задачі (pg-boss, схема `pgboss` у тій самій базі) стартують разом з API: автоскасування
неоплачених за 3 дні карткових замовлень, нагадування про непідтверджені дзвінком, строки «під
розмір», очищення кошиків і старих запитів «Купити в 1 клік», тижневий звіт.
